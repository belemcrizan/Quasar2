# QUASAR2 v0.1.1 — Redundancy Pruning

**Status:** implemented and regression-tested  
**Scope:** one intentionally narrow prerequisite for the frozen v0.2 protocol

v0.1.1 preserves the v0.1 hypothesis generator, retrievers, evidence scorer,
posterior-like updater, decision thresholds, and fixed `EXPLORE` precedence. It
changes only whether a redundant acquisition is allowed to reach the retriever.

## Problem reproduced in v0.1.0

In the canonical astronomy trace, round 1 contrasted exoplanet transit and
black-hole accretion. After its belief update, the discriminator produced the
same two strings for round 2. v0.1.0 executed both searches, received no novel
candidate-document evidence, left the belief unchanged, and then selected
`ASK` because the exploration budget was exhausted.

The duplicate-evidence guard prevented false confidence, but not wasted calls.

## Query identity

Each retrieval is identified by

\[
q_{id}=\operatorname{SHA256}(H_i\;\Vert\;\texttt{NUL}\;\Vert\;
\operatorname{normalize}(q)).
\]

Including the hypothesis id is deliberate: the same text used to test two
different hypotheses represents two distinct hypothesis-conditioned actions.
Normalization makes identity stable under case, accents, punctuation, and
irrelevant whitespace.

The complete hash is recorded in every `RETRIEVAL` event. A proposed query whose
hash already exists is recorded in `EXPLORATION_PRUNED` and is not executed.

## Two stopping gates

### 1. Exact-query gate

Before an `EXPLORE` round starts, proposed queries are compared with the issued
query history. Repeated queries are removed. If all proposals are removed, the
decision engine is evaluated once with exploration disabled. The existing
policy therefore chooses `ASK`, or a forced `ANSWER` in the `noAsk` ablation.

### 2. Zero-novel-evidence gate

After a distinct exploration query executes, the pipeline sums its novel
evidence items. If the sum is zero and the unchanged v0.1 policy would request
another `EXPLORE`, the next acquisition is suppressed and the decision engine is
re-evaluated with exploration disabled.

This gate does not claim that future information gain is mathematically zero.
It is the explicit v0.1.1 heuristic baseline required by the v0.2 protocol.

## Telemetry contract

| Field/event | Meaning |
|---|---|
| `query_hash` | Stable identity of one executed hypothesis-conditioned query |
| `retrieval_calls_avoided` | Number of retrieval calls rejected before execution |
| `pruned_explorations` | Acquisition cycles in which a redundancy gate fired |
| `termination_reason` | `decision_answer`, `decision_ask`, `repeated_query`, or `zero_novel_evidence` |
| `document_novelty` | Fraction of documents not seen in earlier retrieval calls |
| `total_variation` | Per-update movement between consecutive belief states |
| `observed_entropy_reduction` | Previous entropy minus new entropy; may be negative |

The per-step definitions are

\[
TV(b_{t+1},b_t)=\frac12\sum_i|b_{t+1}(H_i)-b_t(H_i)|,
\]

\[
DocumentNovelty_t=1-\frac{|D_t\cap D_{<t}|}{\max(1,|D_t|)},
\]

and

\[
ObservedEntropyReduction_t=H(b_t)-H(b_{t+1}).
\]

## Canonical regression invariant

For the query

```text
The starlight keeps dipping when something crosses the disk
```

the acceptance test requires:

- predicted hypothesis remains `astro.exoplanet_transit`;
- final action remains `ASK`;
- executed exploration rounds fall from 2 to 1;
- retrieval calls fall from 7 to 5;
- two repeated calls are reported as avoided;
- no two executed `RETRIEVAL` events share a query hash.

This is a mechanism-level result, not evidence of general quality improvement.
The full benchmark must verify whether call savings occur without a measurable
loss of intent recovery or correct autonomous resolution.

## Frozen seed-42 benchmark result

The 120-query benchmark produced zero changes in predicted hypothesis, final
action, correctness, Recall@10, reciprocal rank, or nDCG@10 for every pipeline
and baseline record. Call changes were:

| Variant | v0.1.0 calls | v0.1.1 calls | Calls avoided |
|---|---:|---:|---:|
| Full | 4.1917 | 3.8083 | 0.3833 |
| noUpdate | 5.7583 | 4.5083 | 1.2500 |
| noAsk | 4.1917 | 3.8083 | 0.3833 |

The other variants and direct baselines did not issue redundant exploration
and therefore did not change. These figures support H5 only on the bundled
synthetic fixture; a non-inferiority claim requires the preregistered multi-seed
and held-out protocol in v0.2.

## Configuration

```json
"exploration": {
  "deduplicate_queries": true,
  "stop_on_zero_novelty": true
}
```

Both switches are explicit so the original v0.1 behavior can be reconstructed
for controlled comparisons.
